# pubmirror design

pubmirror guards what a private repository publishes. A repository that adopts it
carries a manifest, three hook shims and one pipeline.

Scanning runs on every commit and every push. Publishing is a separate act on a
named commit, approved with a tuple that lives outside the repository.

## Threat model

The guard is against accident and carelessness: a publish cannot happen as a side
effect of ordinary work, and every layer refuses by default. It does not defend
against someone who holds the owner's credentials and sets out to publish.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | clean |
| 1 | the check ran and found something |
| 2 | the check could not run: manifest, denylist, gitleaks, git |

A hook warns on 2 and lets the commit through. CI, the forge guard and the
publisher refuse on 2.

## Commands

| Command | Behavior |
|---|---|
| `check [--staged \| --commit X]` | classification plus scan of the public set |
| `check --history A..B` | every blob, message and identity the range introduces |
| `check-msg <file>` | exact mode: scans the message and the author identity |
| `guard-push` | pre-push: refuses the manifest's public remote; otherwise `check` on the pushed tip |
| `guard-receive` | pre-receive on the canonical forge: refuses a push that carries a finding (§ Forge guard) |
| `stage --commit X [--out DIR]` | builds the public tree; prints `X`, tree hash `H`, denylist hash `D`, and the diff against the last published tree |
| `publish --approve X:H:D` | the publisher guards below |
| `verify` | anonymous clone, rescan of public history, tree hash equal to `H`, the manifest's verify commands |
| `install` | hook shims under the git common directory, chained to `.git/hooks/<name>` |

Every command reads git objects of a named commit or the index. None reads the
working tree.

## Manifest

`.pubmirror.toml` at the repository root.

```toml
version = 1
mode = "snapshot"                     # snapshot | exact

[public]
remote = "git@github.com:OWNER/REPO.git"
author = "Name <address>"

[paths]
public   = ["cmd/", "go.mod", "README.md"]
internal = ["docs/internal/"]

[[fixture]]
path = "testdata/sample.wav"
sha256 = "…"
provenance = "synthetic, generated by …"

[[allow]]
rule = "ip"
match = "10.0.0.5"
path = "internal/net/"
reason = "test address"

[verify]
commands = ["go build ./..."]
```

- A path entry ending in `/` covers its subtree; any other entry is one file.
  Matching is by path segment. The most specific entry wins.
- A file that matches no entry is unclassified, and `check` reports it.
- Snapshot mode: `.pubmirror.toml`, the hook shims and the pipeline file are
  internal without being listed.
- Exact mode: `internal` must be empty, and the manifest is scanned like any file.

## Scanner rules

| Rule | Refuses |
|---|---|
| `home-path` | `/Users/<name>`, `/home/<name>`, `C:\Users\<name>` |
| `ip` | any IPv4 or IPv6 literal except loopback, unspecified and the documentation ranges |
| `private-url` | `ssh://` git URLs, and any URL whose host is on the denylist |
| `email` | any address other than the manifest's public author |
| `token` | gitleaks findings |
| `denylist` | the owner's private values |
| `data-file` | a file under a `testdata/` or `defaults/` directory, an audio, model, dataset or archive extension, a binary file, a git-annex pointer or symlink, without a `[[fixture]]` entry |
| `link` | a symlink that leaves the tree; `.gitmodules` URLs on the denylist |
| `identity` | exact mode: an author or committer other than the manifest's |
| `size` | a file over 50 MB |

An `[[allow]]` entry names one rule, one match, one path scope and a reason. For
the `denylist` rule the match is `token #N`, never the value. Every report lists
the entries that fired.

## Denylist

The owner's private values, in a file outside every repository:
`$PUBMIRROR_DENYLIST`, else `~/.config/pubmirror/denylist.txt`.

- One entry per line. `#` starts a comment. Blank lines are skipped.
- An entry matches as a case-insensitive substring. `word:<entry>` matches whole
  words only.
- An absent or empty file is exit 2.
- A report names an entry as `token #N`, N being its line among the entries.
- `D` is the first 16 hex digits of the SHA-256 of the entries, lower-cased,
  sorted, joined by newlines.

## Forge guard

`guard-receive` is the pre-receive hook of the canonical repository on the
forge. The client hooks can be missing and CI runs after the push is accepted;
this guard judges a push before the forge accepts it. Each pushed ref is judged
by the manifest at its new tip:

| Ref | Judged |
|---|---|
| no manifest at the new tip | nothing; the denylist is not read |
| a deletion | nothing: it carries no content |
| exact mode, any ref | every commit the push brings into the repository (`<tip> --not --all`): blobs, messages, author and committer; an annotated tag's message and tagger |
| snapshot mode, `main` | the public set of the new tip, as `check --commit`: what a publish would carry |
| snapshot mode, another ref | nothing: only `main` is published |

- Commits the repository already holds are not judged again, so a finding
  accepted before the guard existed does not block later pushes.
- Exit 1 and exit 2 both refuse: the forge accepts nothing it could not judge.
  A missing denylist or gitleaks refuses every push to a repository with a
  manifest, and no other.
- A clean ref prints one summary line with `D`; a refused one prints the whole
  report and the ref.
- A canonical that is public on the forge uses exact mode. In snapshot mode the
  forge would serve the internal paths and the private history, which the guard
  does not read.

## Approval

`X:H:D` — X the canonical commit (40 hex), H the git tree hash of the public tree
staged from X (40 hex), D the denylist hash (16 hex). `stage` prints it; a reviewer
reads the staged tree; the approver passes it to `publish`.

## Publisher guards

- X is reachable from a fresh fetch of the canonical `main`.
- The tree staged from X hashes to H; the loaded denylist hashes to D.
- Snapshot: one commit authored as the manifest's author with a UTC date, a
  `Canonical-Commit: X` trailer, and the message `publish <short X>` plus an
  optional scanned summary line.
- Exact: `check --history <last published>..X`, then X is pushed.
- One ref is written: the public `main`. Never a force push.
- On a rejected push: refetch, then compare the public tip's canonical commit
  with X. A descendant of X: superseded, exit 0. An ancestor of X: restage and
  retry. Equal: nothing to do, exit 0. A tip with no canonical commit: exit 1.

## Packages

| Package | Holds | Imports from this module |
|---|---|---|
| `internal/manifest` | parse, validate, classify | — |
| `internal/gitobj` | files and blobs of a commit or the index, commit metadata, ranges, tree hashing | — |
| `internal/scan` | the rules, the denylist, the gitleaks adapter | — |
| `internal/stage` | the public tree of a commit | `manifest`, `gitobj` |
| `internal/publish` | the publisher guards and the push | `manifest`, `gitobj`, `stage`, `scan` |
| `internal/verify` | the anonymous clone and its checks | `manifest`, `gitobj`, `scan` |
| `internal/hooks` | the shims and `install` | — |
| `cmd/pubmirror` | one file per subcommand, registered from `init` | all |

`internal/scan` takes plain inputs so it builds and tests alone:

```go
type File struct {
	Path string
	Mode uint32 // git file mode
	Data []byte
}

type Finding struct {
	Path  string
	Line  int    // 0 when the finding is about the file, not a line
	Rule  string
	Match string // masked for the token and denylist rules
}
```
